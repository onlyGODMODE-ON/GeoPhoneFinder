## სწრაფი გაშვება

საჭიროა Node.js **20+** (გატესტილია 22-ზე). ბაზის დაყენება **არ არის საჭირო** დეველოპმენტისთვის.

```bash
npm install
npm run dev
```

გახსენით **http://localhost:5173**. (API მუშაობს `:3001`-ზე, Vite ავტომატურად აპროქსირებს `/api`-ს.)
ბაზა ამ რეჟიმში არის **PGlite** (რეალური PostgreSQL WASM-ად, მეხსიერებაში); სქემა და დემო მონაცემები გაშვებისას თვითონ იტვირთება.

### ერთი სერვერი (პროდაქშენის მსგავსად)
```bash
npm run build      # frontend/dist
npm start          # API + ფრონტენდი: http://localhost:3001
```
სერვერი თვითონ აწვდის პროდუქტის გვერდებს SEO-თი (title, canonical, JSON-LD), `robots.txt`-ს და `sitemap.xml`-ს.

### რეალური PostgreSQL-ით
```bash
docker compose up -d db
DATABASE_URL=postgres://phonefinder:phonefinder@localhost:5432/phonefinder npm run dev
```
მიგრაციები ავტომატურია (`npm run migrate`). ყველა გარემოს ცვლადი — [.env.example](.env.example).

### ტესტები
```bash
npm test                                                  # ბექენდი (191) + ფრონტენდი (54)
TEST_DATABASE_URL=postgres://... npm test -w backend      # იგივე 191 ტესტი ნამდვილ PostgreSQL-ზე
```

### უახლესი რაუნდის ცვლილებები

**საძიებო ღილაკის საიმედოობა.** `/search` გვერდზე საძიებო ველი და ღილაკი ადრე ჩნდებოდა მხოლოდ მას შემდეგ, რაც კატალოგის

სკელეტონით იცვლებოდა, საძიებო ველთან ერთად, და ღილაკზე დაჭერას აზრი არ ჰქონდა, სანამ ის საერთოდ არ გამოჩნდებოდა.
ახლა საძიებო ველი და ღილაკი **მაშინვე** იტვირთება, დამოუკიდებლად მეტამონაცემებისგან — მხოლოდ გვერდით ფილტრების პანელი
ელოდება ცალკე (თავისი ჩატვირთვის ეკრანით). ძიება მუშაობს დაუყოვნებლივ, თუნდაც ფილტრები ჯერ არ იყოს ჩატვირთული.

**ნამდვილი ჩატვირთვის ეკრანი ცარიელი ეკრანის მაგივრად.** მთავარ გვერდზე რეკომენდაციის ბლოკს (და ძიების ფილტრებს)
სჭირდება იგივე `/api/meta`, რომლის პირველი ჩატვირთვა (მთელი კატალოგის დამუშავებას სჭირდება დრო) ნელი შეიძლება იყოს.
ადრე ამ დროს უბრალო ნაცრისფერი მართკუთხედი ჩანდა. ახლა ნაცვლად ამისა ჩანს spinner + მოძრავი, დამამშვიდებელი ტექსტი
("სერვერთან დაკავშირება…", "კატალოგი იტვირთება…"), რომ მომხმარებელმა იცოდეს, რომ რაღაც ხდება.

**iCity და iMobi ამოღებულია** მაღაზიების სიიდან — დარჩა 7 მაღაზია: Zoommer, Alta, Elit Electronics, Megatechnica, iStore,
GStore, Xiaomi Georgia.

**პროცესორისა და გრაფიკული ბარათის დეტალები.** პროდუქტის გვერდზე, შედარებასა და რეკომენდაციის ბარათის გაშლილ ხედში
ახლა ჩანს არა მხოლოდ ჩიპსეტის სახელი, არამედ **ბირთვების კონფიგურაცია** (მაგ. "8-core (1+3+4)"), **CPU/GPU ქულა**
(0–100, შედარებისას საუკეთესო მონიშნულია ✓-ით), **გრაფიკული ბარათის რეალური მოდელის სახელი** (მაგ. "Adreno 750",

და ბარათის გაშლისას წერია "საერთო ქულა (ყველა კატეგორიის საშუალო)" ჩვეულებრივი "საბოლოო ქულის" ნაცვლად. *ეს არის შეგნებული გადახვევა

**მთავარი გვერდი აღარ "იჭედება".** ბაგი იყო ის, რომ ბექენდის პირველი გაშვებისას (მთელი კატალოგის ჩატვირთვას გარკვეული დრო სჭირდება)
ფრონტენდს არანაირი განმეორებითი მცდელობა არ ჰქონდა — თუ პირველი მოთხოვნა ვერ მოხვდებოდა მზად სერვერზე (ან სერვერს პასუხი ჯერ არ ჰქონდა
დამზადებული, 503), მომხმარებელს პირდაპირ შეცდომის გვერდი უჩნდებოდა და ხელით გადატვირთვა სჭირდებოდა. ახლა `useAsync` ავტომატურად
იმეორებს მოთხოვნას მზარდი დაყოვნებით (თანდათან 4 წამამდე), სანამ სერვერი მზად არ იქნება — მომხმარებელი ამას საერთოდ ვერც კი ამჩნევს,
უბრალოდ ჩატვირთვის ეკრანი ოდნავ დიდხანს ჩანს. მხოლოდ ნამდვილი შეცდომის შემთხვევაში (მაგ. ბაზა ნამდვილად გაფუჭებულია) უჩნდება

## როგორ მუშაობს რეკომენდაცია

მთელი ლოგიკა **ბექენდზეა** (`POST /api/recommendations`), UI მხოლოდ აგროვებს არჩევანს და აჩვენებს შედეგს.

1. **მკაცრი ფილტრები** → *Candidate Array*: ფასი (`min … max × 1.05`, ტოლერანტობა ავტომატურია და კლიენტიდან არ იცვლება), ბრენდი, მაღაზია,
   **არასავალდებულო ტექნიკური მინიმუმები**. ფასი = **ყველაზე იაფი მიმდინარე, ხელმისაწვდომი შეთავაზება არჩეული მაღაზიებიდან**.
2. ფასის კლებადობით დალაგება. 3. **ლექსიკოგრაფიული** დალაგება პრიორიტეტებით (სტაბილური).
4. **FinalScore** = `Σ(ქულა × წონა) / Σ(წონა)`, წონები `N … 1`; დალაგება FinalScore-ით (სტაბილური). ტოლობისას რჩება ლექსიკოგრაფიული, შემდეგ ფასის კლებადობის რიგი.
5. **Top 10**; თუ ნაკლები ვარგისია, ნაჩვენებია რეალური რაოდენობა — სია არასდროს ივსება გამოგონილი ვარიანტებით.

პრიორიტეტების გარეშე ბოლო რიგი = ფასის კლებადობა. **გამოტოვებული მონაცემი ნულად არასდროს ითვლება**: ფაქტორი გამოირიცხება, ხოლო თუ ვერაფერი ითვლება — ქულა `null`-ია ("—").

### ახალი პრიორიტეტის დამატება
1. `scoring/definitions.js`-ში დაამატეთ ობიექტი; 2. `key` — `domain/constants.js`-ის `PRIORITIES`-ში და `frontend/src/lib/priorities.js`-ში;
3. თარგმანები `ka.js`/`en.js`-ში (`priority.*`, `priorityHint.*`) — ტესტი დაგიჭერთ, თუ გამოგრჩათ. ფორმულის შეცვლისას გაზარდეთ `version`.
