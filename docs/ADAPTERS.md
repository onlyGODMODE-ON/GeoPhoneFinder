# მაღაზიის (ადაპტერის) დამატება და რეალურ მონაცემებზე გადასვლა

რეკომენდაციის ძრავმა, სკორინგმა და UI-მ **არ იციან**, რომელი მაღაზიები არსებობს. მაღაზია არის ბაზის ჩანაწერი
(`stores` ცხრილი) + ერთი პატარა ადაპტერის კლასი, რომელიც მაღაზიის მონაცემებს საერთო ფორმატში აბრუნებს.

> ამ პროექტის აგებისას რეტეილერების საიტებთან წვდომა არ მქონდა (ქსელი დაბლოკილი იყო), ამიტომ **არცერთი რეალური
> ადაპტერი არ არის შემოწმებული**. ქვემოთ აღწერილი მექანიზმები ტესტებითაა დაფარული სინთეტიკურ მონაცემებზე.

## რას აბრუნებს ადაპტერი და საიდან მოდის დანარჩენი

ადაპტერს **მხოლოდ ლისტინგი** სჭირდება: სათაური, ფასი, **ზუსტი პროდუქტის ბმული**, ხელმისაწვდომობა, **ფოტოს URL**, ფერი.
ტექნიკურ მახასიათებლებს (პროცესორი, კამერა, ბატარეა…) მაღაზიის feed იშვიათად იძლევა, ამიტომ ისინი მოდის
**სპეც-კატალოგიდან** (`backend/src/ingestion/spec-catalog.js`) მოდელის (brand + model) მიხედვით.

| ველი | სად ხვდება | რას აკეთებს UI-ში |
|---|---|---|
| `url` | `store_offers.url` | ღილაკი "X-ში ნახვა" ხსნის **ზუსტად ამ მაღაზიის ზუსტად ამ ვარიანტის** გვერდს |
| `imageUrl` | `store_offers.image_url` | ბარათზე ჩანს იმ მაღაზიის ფოტო, რომელსაც საუკეთესო ფასი აქვს; პროდუქტის გვერდზე — ყველა მაღაზიის ფოტო გალერეაში |
| `color` | `store_offers.color` | ფერის ტეგი; ფოტოს არარსებობისას ილუსტრაცია ამ ფერით იხატება. თუ feed-ში არ არის, სათაურიდან იკითხება ("… 8/128GB Light Violet") |
| `title` | პარსერი | ბრენდი, მოდელი, RAM, მეხსიერება. ანადგურებს მაღაზიის მოდელის კოდებს (`A376ED`, `S948`, `A175F/DS`) — გატესტილია **რეალურ Zoommer-ის სათაურებზე** |

სპეც-კატალოგში მოდელი რომ არ არის: ვარიანტი მაინც იქმნება (RAM/მეხსიერება სათაურიდან), მაგრამ დანარჩენი ქულები **უცნობია (`—`)**,
არასდროს გამოგონილი. ახალი ტელეფონის დასამატებლად კატალოგში ერთი ობიექტი ემატება. `model` უნდა ემთხვეოდეს პარსერის
ნორმალიზებულ სახელს (მაგ. `Galaxy A55 5G`, არა `Galaxy A55 A556B 5G`).

## 1. ჩაწერეთ მაღაზია
`backend/src/ingestion/stores.js`:
```js
{ id: 'mymarket', name: 'My Market', baseUrl: 'https://mymarket.ge', adapterKey: 'mymarket' }
```
გაშვებისას ჩანაწერი ბაზაში ავტომატურად ჩაჯდება. `UPDATE stores SET active = false ...` მაღაზიას რეკომენდაციებიდან ამოიღებს.

**ახლანდელი მაღაზიები (7):** Zoommer, Alta, Elit Electronics, Megatechnica, iStore, GStore, Xiaomi Georgia.
✔ დადასტურებული დომენები — `zoommer.ge`, `alta.ge`, `istore.com.ge`.
❓ **არ არის დადასტურებული** (ჩემი ვარაუდი) — `eliteelectronics.ge`, `megatechnica.ge`, `gstore.ge`; Xiaomi Georgia-ს URL placeholder-ია.

iCity და iMobi მოცილებულია სიიდან მომხმარებლის მოთხოვნით.
გადაამოწმეთ `stores.js`-ში, სანამ რეალურ რეჟიმზე გადახვალთ.

## 2. დაწერეთ ადაპტერი
`backend/src/ingestion/adapters/registry.js` — თითო მაღაზია ერთი კლასია:
```js
class MyMarketAdapter extends StoreAdapter {
  // ვარიანტი A: ოფიციალური JSON feed. საკმარისია env: FEED_URL_MYMARKET=https://...
  mapRecord(r) {
    return {
      sourceProductId: String(r.sku),
      url: r.productUrl,           // ზუსტი პროდუქტის გვერდი!
      title: r.name,               // "Samsung Galaxy A37 A376ED 5G 8/128GB Light Violet"
      price: Number(r.priceGel),
      available: r.stock > 0,
      imageUrl: r.image,           // მაღაზიის ფოტო
      color: r.color,
    };
  }
  // ვარიანტი B: საკუთარი API/HTML ინტეგრაცია
  // async fetchLive() { ...გადმოწერე და დააბრუნე RawListing[]... }
}
```
`ADAPTERS`-ში დაამატეთ `mymarket: MyMarketAdapter`. გაშვება: `ADAPTER_MODE=live FEED_URL_MYMARKET=… npm run ingest`.

## RawListing კონტრაქტი
იხილეთ `backend/src/ingestion/validate.js`. სავალდებულოა: `sourceProductId`, `url` (http/https), `title`, `price` (GEL, > 0), `available` (boolean).
არასავალდებულო: `brand`, `model`, `ram`, `storage`, `imageUrl`, `color`, `specs`, `fetchedAt`.
**უცნობი მნიშვნელობა გამოტოვეთ. არასდროს ჩაწეროთ 0 ან გამოგონილი მნიშვნელობა.**

## ფოტოები — რაზე უნდა იფიქროთ
- `imageUrl` პირდაპირ მაღაზიის CDN-ზე მიუთითებს (hotlink). `<img>` იყენებს `referrerPolicy="no-referrer"`-ს და, თუ სურათი ვერ ჩაიტვირთა, ავტომატურად გადადის ილუსტრაციაზე.
- ზოგი მაღაზია hotlink-ს კრძალავს, ზოგს სურათებზე უფლება სჭირდება. **გაითვალისწინეთ საავტორო უფლებები და მაღაზიის პირობები.**
  თუ ნებართვა გაქვთ, კარგი გაუმჯობესებაა სურათების საკუთარ სერვერზე ჩამოტვირთვა/პროქსი (ამჟამად არ არის).

## რას აკეთებს ძრავი თქვენს მაგივრად
- ვალიდაცია და **კარანტინი** ბროკენ ჩანაწერებისთვის (`source_records.status = 'quarantined'`);
- ერთი და იგივე ტელეფონის სხვადასხვა მაღაზიიდან გაერთიანება **ერთ ვარიანტად** (RAM/მეხსიერება/ჩიპსეტი/5G თუ განსხვავდება, ცალკე ვარიანტია) — ტესტი ამოწმებს, რომ 7 მაღაზიის 7 სხვადასხვა სათაურის სტილი ერთსა და იმავე 219 ვარიანტში ერწყმის;
- ფასის/ხელმისაწვდომობის ცვლილებების ლოგირება (`update_logs`);
- რასაც მაღაზია აღარ ყიდის — `available = false`;
- **მარცხის შემთხვევაში წინა მონაცემები ინახება**; ცარიელი feed ითვლება მარცხად და არა "ყველაფერი გაიყიდა".

## კანონიერება
პირველი არჩევანი: ოფიციალური API / partner feed / structured data. HTML scraping — მხოლოდ თუ მაღაზიის პირობები,
robots.txt და კანონმდებლობა ამის უფლებას იძლევა. `createPoliteFetcher` (`ingestion/http.js`) იძლევა rate limit-ს, კეშს და backoff-ს.

## დემო რეჟიმის ბმულები
დემოში პროდუქტის რეალური გვერდები არ არსებობს, ამიტომ ღილაკი ხსნის **ამ მაღაზიის დომენით შემოფარგლულ ძიებას** ზუსტად ამ ტელეფონზე
(`storeSearchUrl` — `stores.js`). მაღაზიების შიდა ძიების URL ფორმატები დადასტურებული არ მქონდა. რეალურ რეჟიმში ბმული ყოველთვის
ადაპტერის მიერ დაბრუნებული ზუსტი გვერდია.
